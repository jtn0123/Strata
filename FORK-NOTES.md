# Justin's Strata Mac experiment

This fork starts from Niko1221/Strata commit `82f46a8c8f475f001ad76d92f58f4a4f8ffb0253` (v0.1.40.1). The `main` branch tracks that parent checkpoint. Mac work lives on `mac-m5-lab`, under [macos/lab](macos/lab/README.md).

The lab was imported through Git subtree without squashing. Its original setup, conversation-caching, prediction-helper and source-review commits remain in this branch's ancestry. [Raw results](macos/lab/bench/RESULTS.md), [prediction tradeoffs](macos/lab/bench/PREDICTION.md) and the [October 6 source review](macos/lab/bench/UPSTREAM-SCAN.md) are preserved.

The tested profile uses the pinned Strata macOS API shell and native llama.cpp Metal engine defined in `macos/lab/config/runtime.json`. Importing the lab into this fresh parent fork does not upgrade either runtime. The actual benchmarks were measured from the original `Strata-Mac-Lab` directory; absolute paths in their immutable records describe that machine and run.

Current everyday result: full Qwen3.8-Flash-Next GSQ-RCO Q2_0, all experts, lazy SSD lookup, 4K context, batch 512 and conversation caching, about 37–39 output tokens/s on the 48 GB M5 Pro. The smaller prediction helper is an optional measured profile. Tools and images remain outside the verified adapter scope.

Meld Turbo's focused Q2_0 Metal math patch is now benchmarked in an isolated native build. It passed 122 Q2 GPU checks, two Q4 controls, six offline workflow tests and 54 candidate full-model answer checks. Six sustained baseline/candidate passes completed, with 108/108 answer checks across both engines. The last confirmation measured +0.3% / +3.7% writing speed for short/long inputs, slower input processing and little overall reply-time benefit. Background work affected earlier passes. [Measured results, raw evidence and the decision](macos/lab/bench/Q2-METAL.md) explain why the normal launcher retains the original engine.

The later [shared-helper experiment](macos/lab/bench/SHARED-HELPER.md) removes 521 MiB of duplicated helper weights and packs CPU expert tables ahead of small GPU tensors. This lowers the helper's mixed-placement Metal mapped-weight span from 1,183 MiB to 45.6 MiB. Eight paired passes at temperature 0.6 completed 240 answer checks with no new swap. Compared with the old helper, packed mixed placement generated synthetic writing 7.7-11.6% faster and finished cached ledger replies 7.0-11.0% sooner. Code TPS changed only +0.7%. Long fresh-input replies still finish later than prediction-off operation, so the ordinary default stays in place. A separate `Start Strata - Shared Prediction Test.command` launches the tested optional profile.

The independent [draft-vocabulary experiment](macos/lab/bench/DRAFT-VOCAB.md) passed 180 answer checks. Its corrected GPU output path improves synthetic generation about 4% over the full helper, but cached generation slows 9-10% and the compact table adds memory. It stays optional and is not combined with shared weights. Cross-session caching remains deferred. The shared profile also passed nine real Strata API checks, all nine tokenizer metadata comparisons, and the final 21 offline checks. Fresh-clone reprovisioning failures were reproduced and fixed: regenerated helper files must match their saved hashes, without changing the registry pins.

The later [helper depth/worker tuning](macos/lab/bench/HELPER-TUNING.md) compares against fresh two-token/eight-worker controls. Four-token prediction improves longer cached ledger generation from 48.1 to 56.4 TPS (+17.2%) and complete reply time by 9.2%, but slows prose and Chinese writing. One token improves short synthetic writing from 42.7 to 44.5 TPS (+4.2%) and Chinese writing from 36.1 to 42.0 (+16.3%); cached generation slows. Three tokens improves the code test from 45.9 to 48.2 (+5.0%). Six/twelve helper workers add less than 1% generation speed, so eight stays in place. Optional writing and fast-follow-up launchers expose the measured settings; the ordinary and balanced launchers retain their defaults. Fourteen benchmark passes complete 420 answer checks with zero new swap. All 27 real API checks pass after a reproduced quick-restart port-check bug was fixed, and all 26 offline checks pass.

Model weights, virtual environments, downloaded vendor trees and active runtime files are ignored. They are reproduced with the lab's pinned provisioning/download tools; no model weights are stored in this repository. The original working lab remains in place with the isolated builds and derived helpers ready, and no model server left running. Colima stayed stopped through both speed sweeps; it was restarted outside this work afterward, and later app-check memory records include new system swap. This run did not start or restart the VM. Comparison commands print a plan unless given `--run`; the app launchers load the selected model when opened.

The local `upstream` remote is fetch-only (`pushurl=no_push`) and `origin` points to Justin's fork. Future lab changes can be imported from the original local repository with another subtree update, preserving experiment history.

The later [few-row GPU math trial](macos/lab/bench/METAL-MMA.md) applies the exact dense Metal patch from llama.cpp PR #30065 (`b0cb151`) on top of the existing shared-helper patch in an isolated `mtp-mma` build. Real-model diagnostics confirm 13 new-format pipeline variants; 1,076 CPU-reference GPU math checks, all 30 offline checks, 360 benchmark answer checks and 27 real app API checks pass. All twelve speed passes and all three app trials record zero new swap. Colima was stopped again with the user's authorization and left stopped; no model server remains running.

Matching-depth comparisons show roughly 17% more output TPS at three-token prediction and 20-22% more at four. The writing launcher now selects the GPU patch with three predicted tokens: short synthetic writing improves from this suite's freshly remeasured prior one-token profile, 43.85 to 48.91 TPS (+11.53%), and complete reply time falls 7.67%. This writing upgrade changes both depth and kernel. At unchanged depth three, code improves 48.12 to 56.21 TPS (+16.81%) and complete reply time falls 13.30%. The fast follow-up launcher now selects the patch at depth four: longer cached-ledger generation improves 57.70 to 69.24 TPS (+20.00%) and complete reply time falls 11.09%. These cached replies are short; their rate is not a general writing result. The ordinary and original balanced launchers retain their earlier engine/settings. Model files, routed expert kernels, the lazy SSD lookup path and GPU memory limit are unchanged. The report preserves all matching controls, variation, raw measurements and validation limits.

The user subsequently authorized the [first M5 testing batch](macos/lab/bench/M5-RESULTS.md) after memory cleanup. Four comparisons complete twenty full-model passes with 600 passing answer checks, zero observed swap growth, and at least 2.448 GiB available RAM. All 4,004 prerequisite CPU-reference GPU math checks, nine depth-six real app/API check groups and 40 offline workflow checks pass. Stock timing diagnostics at depths three/four produce valid command-buffer timestamps; their timings are excluded from speed results and do not measure hardware accelerator occupancy.

Keep the existing Tensor API enabled: on the depth-three 2048-token input it processes 535.07 versus 312.08 input tokens/s, reaches the first token in 3.8283 versus 6.5633 seconds, and completes the reply in 6.3823 versus 9.2263 seconds. That path was already enabled, so this confirms an existing benefit. Floating-point path changes also alter token choices/helper acceptance; generation differences are not a pure kernel-speed measurement.

Keep writing at depth three: the fresh code control measures 56.43 TPS, versus 53.54 at depth five (-5.12%) and 50.38 at six (-10.72%). Keep the existing long-follow-up launcher at four. The new optional `Start Strata - Short Structured Follow-ups Test.command` selects six: in the matched 512-token cached-ledger test it raises 68.98 to 75.50 TPS (+9.44%) and reduces complete reply time 0.6252 to 0.5947 seconds (+4.88% quicker). Those are 25-token structured answers. The 2048-token cached case is essentially tied, so this is a narrow optional trial rather than a general writing upgrade.
